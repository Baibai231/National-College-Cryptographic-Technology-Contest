# 03｜相关顶会论文、尚存边界与可执行研究路线

> 核查日期：2026-09-14。前提：保留当前工程基础，一个月内优先形成可验证的研究原型，而不是承诺一个月达到顶会发表标准。本文件给出论文方法与代码落点、数学定义、实验设计和退出条件；没有把计划当成已完成成果。

## 一、建议最终做什么

建议核心题目先收敛为：

**“受限交互条件下的网站口令政策可靠推断、反馈一致性与可测性偏差研究”。**

人话解释：不再问“我能给这个网站打多少安全分”，而是问：

1. 不注册账号时，究竟能可靠测出哪些口令规则？
2. 页面告诉你的“可以/不可以”，什么时候可信，什么时候是门槛、异步反馈或强度提示造成的假象？
3. 为什么一些网站一直测不到，遗漏它们会把结论带偏多少？
4. 在少量授权账号或本地真值环境中，前端观察与实际接受相差多少？

这个对象直接涉及口令猜测、接受集合、凭据暴露与认证边界，比宽泛的“网站安全评估”更集中。但题目本身不是新颖性证明；需要下面的基线、消融、保留集与复现实验。

数据动机已经存在：303站历史基线中只有61站记录到密码框，16站开始主动测量，5站满足现有完整门控；最新413站双入口实验有348条unknown和233条错误。详细口径见[第二份文档](02_项目结构缺陷与实测数据.md)。这些数字说明可靠性和可测性是真问题，不证明我们提出的解法一定有效。

## 二、如何理解“论文没做的事”

必须区分三种说法：

- **作者明确局限**：论文自己承认的模型、样本或实验限制，可以准确引用。
- **研究范围不同**：论文解决A而没有研究B，不等于其方法有缺陷。
- **我们的候选创新**：推测某种补充可能有效，尚需更全面文献检索和实验证明。不能写“没人做过”。

本次是与当前项目直接相关的重点文献审阅，不是穷尽数据库的系统综述。因此以下使用“值得验证”“可扩展”，不使用“首次”“填补空白”的结论性措辞。

## 三、论文一：创建政策的黑盒推断——主基线

**Suood Alroomi、Frank Li，Measuring Website Password Creation Policies At Scale，ACM CCS 2023。** [作者原文](https://faculty.cc.gatech.edu/~frankli/papers/roomi_ccs23.pdf)，[项目资料](https://authenticationresearch.cc.gatech.edu/creation.html)。详细对照已放在[第一份文档](01_Frank_Li论文与项目对比.md)。

### 应复用什么

采用“可接受基准密码→保持其他属性不变的受控变异→参数推断→一致性检查”的实验设计。论文已有长度二分，因此二分只能作为基线或工程优化，不是新方法。当前代码的 `password_candidates.py`、`adaptive_policy.py`、`util_test_password.py` 是对应落点。

### 边界与我们可做的事

原文的静态政策假设和复杂流程造成的选择偏差值得继续研究。我们的交互更受限，应关注**有噪声、可弃权的前端判定器**，而不是假装得到了同等服务端证据。

实验设计：同一组已知真值政策，比较原顺序、当前自适应策略、改进的证据/版本空间策略。固定探针预算、输入分布与环境，测规则预测误差和成本。然后在真实低交互站验证可迁移性，并在授权子样本验证服务端一致性。

**候选贡献**：不是更多政策字段，而是噪声下更低误判、可解释弃权、同预算更高有效覆盖。若收益仅来自多等30秒，就如实报告工程权衡，不包装成新算法。

## 四、论文二：强度计的评价不能只看一个分数

**Ding Wang 等，No Single Silver Bullet: Measuring the Accuracy of Password Strength Meters，USENIX Security 2023。** 论文按在线/离线猜测场景采用不同评价方法，包括加权秩相关、KL散度和考虑误判方向的指标，实验涉及12种强度计、14个数据集。[论文与方法摘要](https://www.usenix.org/conference/usenixsecurity23/presentation/wang-ding-silver-bullet)

### 代码已有多少，不能夸大什么

B分支 `application_security/password_meter_evaluation.py` 已含加权 Spearman 等实现，并明确区分数据集准确性与单站提示一致性。这是真实的代码基础，**但不在当前 main，也没有由模块存在推出大规模有效实验的证据**。

建议复用论文的指标定义并按原文核验测试用例。例如，输入已经转换为秩的 x、y，以及密码频率 w：

\[
\rho_w=\frac{\sum_i w_i(x_i-\bar x_w)(y_i-\bar y_w)}
{\sqrt{\sum_iw_i(x_i-\bar x_w)^2\sum_iw_i(y_i-\bar y_w)^2}}.
\]

这里的 w 是实验分布频率，不应凭空设成网站评分权重。若无频率或破解真值数据，就不能声称复现了整套强度计准确性评价。

### 范围差异与可扩展问题

强度计估计“难不难猜”，注册验证器判断“允不允许用”，二者不是同一个函数：网站拒绝一个高强度密码，可能只是超过长度上限，**不自动构成强度计错误**。

我们可以分析二者的联合行为，但必须定义什么才是矛盾：

- 页面明确声称“已满足全部要求”，同一状态的验证器仍因密码规则拒绝：可复现一致性问题。
- 页面标“强”，验证器接受：只说明页面与接受路径相容，不能证明密码真的强。
- 页面标“弱”，验证器接受：可能是宽松政策，不是逻辑自相矛盾；其风险需猜测模型支持。

新增实验输出应保存规则提示、强度标签、接受状态和时间，不把三者压成一个 bool。可研究对用户产生误导的场景，但若没有用户实验，只能报告界面/验证行为，不能声称已经证实用户因此选了弱口令。

## 五、论文三：zxcvbn 作为猜测难度基线，不是熵计算器

**Daniel Lowe Wheeler，zxcvbn: Low-Budget Password Strength Estimation，USENIX Security 2016。** [论文](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/wheeler)，[官方开源实现](https://github.com/dropbox/zxcvbn)。其实现考虑字典、重复、序列、键盘和常见变换等模式，比简单字符集计数更适合作为实用基线。

### 实际怎么接代码

离线固定官方版本/提交、字典与配置，对合成和获准使用的测试候选求 `guesses` 或 `guesses_log10`。不要把候选口令提交给第三方在线强度网站，也不要公开真实用户密码。对动态网站，仅将自己的合成候选送入获准的低交互测量。

\[
g(x)=\log_{10}(\widehat{G}(x)).
\]

这里 \(\widehat{G}\) 是该模型估计的猜测次数，不是严格的香农熵，也不是已证明的最优攻击成本。不要把 \(\ell\log_2|\Sigma|\) 当作人类口令的真实安全强度。

### 可深入但尚需验证

官方模型与字典不能天然代表所有中文、拼音、站点名和本地流行模板。可以在合法来源的受控数据上研究地区/语境的估计偏差，但“加入中文词典”已有很长研究历史，本身不能直接称创新。

更贴近本项目的做法是：在网站接受集合中，评估是否存在模型判为容易猜的**构造见证**，并用另一个攻击模型做敏感性分析。不能因为一个模型输出低分，就宣称网站已可被破解。

如实验分布为 D，接受集合为 A，预算为 B，可定义项目自己的条件指标：

\[
R_B=\Pr_{x\sim D}[\widehat G(x)\le B\mid x\in A].
\]

这是**拟议指标**，不是该论文原公式；它强烈依赖候选分布D。用刻意构造的弱口令集合测到的比例不能解释成用户账号被攻破概率。

## 六、论文四：Leaky Forms——不提交也可能暴露凭据

**Asuman Senol、Gunes Acar、Mathias Humbert、Frederik Zuiderveen Borgesius，Leaky Forms: A Study of Email and Password Exfiltration Before Form Submission，USENIX Security 2022。** 该研究结合字段访问与网络流量，测量提交前的数据收集；公开结果包括52个站的密码被会话回放脚本收集。[论文](https://www.usenix.org/conference/usenixsecurity22/presentation/senol)

### 可直接使用的工具，而不是只引用名字

作者提供 [研究主仓库](https://github.com/leaky-forms/leaky-forms)、[爬虫](https://github.com/asumansenol/leaky-forms-crawler) 和主仓库中的 `leak-detector`、分析材料。方法包括字段访问观测，以及在HTTP流量中匹配填写值及部分编码/散列变换。复用前应核查各仓库许可证、版本和运行条件。

B分支已有 `application_security/leaky_forms.py`，可先与官方测试样例/合成本地真值进行差分验收，不能只根据模块名说已经完整复现。

### 已有研究与候选扩展的边界

“提交前泄露”已被研究过，不能当我们的发现。我们可研究**测量仪器自身的副作用**：运行inline探针时，哪些密码候选会触发实时校验、分析脚本或第三方传输？不同等待策略是否改变观测和外发行为？

区分三件事：脚本读取、发往端点、可证实的不必要第三方凭据暴露。第一方校验请求未必是泄露；“散列后发送”也不自动等于安全或不安全，需要看可逆映射、字典枚举和用途。

事件表示可采用：

\[
e=(\mathrm{run},\mathrm{form},\mathrm{probe},t,\mathrm{action},\mathrm{recipient\_class}).
\]

这是项目建议的脱敏事件模型。用每次实验独立的合成标记做匹配，长期只保留分类与证据摘要，避免保存Cookie、令牌、真实口令或带敏感参数的完整URL。仪器自己的误报/漏报也要用本地已知脚本验证。

**优先度：可作为主线的一个窄而有价值的副实验；不建议同时做成第二个完整追踪生态论文。**

## 七、论文五：MFA/RBA与认证路线——需要账号的扩展线

**Anthony Gavazzi 等，A Study of Multi-Factor and Risk-Based Authentication Availability，USENIX Security 2023。** 对208个支持账号创建的热门站研究MFA/RBA及SSO带来的变化，报告42.31%支持MFA；研究的攻击防护实验不只是观察一个按钮。[原文信息](https://www.usenix.org/conference/usenixsecurity23/presentation/gavazzi)

### 可复用的方法

借鉴“直接登录与SSO路线分别评估”和“具备功能与实际阻止风险事件分别评估”的实验结构。B分支 `auth_graph.py`、`authentication_surface.py`、`recovery_analysis.py` 可以作为记录层，但公开页面图只能代表已观察路径。

定义认证图：

\[
G=(V,E),\quad E=E_{\mathrm{observed}}\cup E_{\mathrm{tested}}\cup E_{\mathrm{unknown}}.
\]

边的这些标记是我们的设计，不能借论文名把它包装成已验证协议模型。未验证的恢复边不能填一个低强度分数；也不能不记录它，然后宣称最强路径就是账号实际安全性。

### 能深化什么、何时停止

在授权测试账号上研究“强主路径能否通过较弱恢复路径绕回”有意义，但此问题并不新。应从一个具体机制、明确威胁模型和少量可重复样本切入。

**退出条件**：拿不到合法测试账号、恢复渠道和明确授权，就停留在路径可见性与未知项报告，不做账户接管、限速或枚举实验，不声称完整评估。一个月主线不应依赖大量账号突然到位。

## 八、论文六：WPSE——从状态机借方法，不能借来安全证明

**Stefano Calzavara 等，WPSE: Fortifying Web Protocols via Browser-Side Security Monitoring，USENIX Security 2018。** 该工作用浏览器侧协议监控约束流程和消息的机密性/完整性，并提供形式化论证与OAuth/SAML实验。[论文与作者](https://www.usenix.org/conference/usenixsecurity18/presentation/calzavara)

### 可落到代码的方法

借鉴有限状态监控：为登录/注册导航及某一种获准观察的协议定义状态、事件和允许转换，而不是页面出现几个词就给最终结论。B分支 `passive_protocol_probe.py`、`jose_validation.py`、`oidc_discovery.py` 是可检查的落点；先界定哪些是离线数据验证、哪些观察真实协议。

\[
q_{t+1}=\delta(q_t,e_t),\qquad \tau=e_1\cdots e_n.
\]

如果只获得部分轨迹 \(\pi(\tau)\)，未见违规不代表完整轨迹安全。状态机公式本身也不是WPSE形式化安全证明的复现；证明依赖具体模型和假设，不能通过引用自动转移到我们的代码。

### 与本项目最贴近的扩展

先用状态守卫解决自己的问题：登录意图不能静默转成注册测量；对照不能跨表单复用；异步校验未结束不能落 definitive verdict。这个工作主要是可靠测量方法，不必夸大成新协议防护系统。

如果要深入OAuth/JOSE，必须挑一个可验证属性并取得完整测试轨迹；仅发现算法名或下载JWKS不能证明服务端真的按该算法验签。

## 九、论文七：Passkeys已有深入研究，不宜当成未经开垦的空白

**Jannett 等，The State of Passkeys: Studying the Adoption and Security of Passkeys on the Web，USENIX Security 2026。** 公开预发表原文描述持续发现、872个部署，以及103站的安全评估。作者明确讨论注册验证门槛、可取得测试账号的服务偏差与认证后端去重困难。[官方原文，尤其§7](https://www.usenix.org/system/files/conference/usenixsecurity26/sec26_prepub_jannett.pdf)

### 对我们意味着什么

Passkey/WebAuthn不是没人做。持续发现、API观察、生命周期、服务端攻击面都已有工作。我们不能只凭“访客模式+漂亮报告”宣称比这些研究更全面。

B分支 `webauthn_observer.py` 已有不主动调用凭据API的观察器，记录公开请求的脱敏摘要，并明确：challenge长度不证明随机性或一次性，RP关系不证明服务器绑定正确，请求参数不证明断言验证正确。这种自我限制应保留。

可以做多来源发现证据融合、误报分析、同后端去重与可测性评估，但是否有足够的新问题需要继续查重。若研究重放、密钥替换、会话绑定等实际安全性质，就需要授权账号和可控实验，访客只看参数不足以得出结论。

**建议：B系列保留为第二阶段能力库。本月不要把“做完整Passkey安全扫描器”设为主线，也不要因它热门就推倒已有口令测量工作。**

## 十、最终推荐的三个研究问题

### RQ1：怎样在低交互、异步和门控条件下可靠识别口令反馈？

落点：`TestPassword` 判定、字段状态、事件时间线与质量门控。

比较：颜色/提示基线、当前负对照策略、同表单绑定+多信号+显式弃权策略。

指标：误接受、误拒绝、弃权率、重复一致率、每站耗时和探针数。不能只比成功站数量。

### RQ2：有限预算下能推断多少真实规则，不能辨识时如何诚实报告？

落点：候选池、版本空间、长度/组合/条件规则模型。

比较：固定序列、当前启发式、新策略；分训练/开发政策和保留政策模板，避免每个网站手工调到成功。

指标：未参与推断候选上的预测误差、规则参数识别率、不可辨识比例、预算曲线。有限观察只能识别等价类时，输出可能政策集合或边界，不强行选择一个。

### RQ3：不可测站让全体结论偏向哪里？

落点：预检分类、停止原因、分层人工样本、可测性报告。

按网站用途、入口门槛、地区/语言和认证路线分层；报告每层覆盖，授权子样本补充服务端对照。不得默认失败样本与成功样本同分布。

这三个RQ互相服务，分类器不再是一个与密码学脱节的单独功能：它决定接受策略可以被观察的范围，以及安全结论能推广到哪里。

## 十二、论文/竞赛报告应有的公式和图，不是装饰

1. **漏斗图**：目标→HTTP→入口→字段→可靠判定→参数→复验，每层列损耗原因。
2. **混淆矩阵**：已知真值下的A/R/弃权，不把弃权藏起来。
3. **成本—误差曲线**：x轴探针或时间预算，y轴保留集预测误差，配有效覆盖率。
4. **重现性图**：同站两轮的可测状态和属性差异；页面改变与算法不稳定分别标注。
5. **可测性分层图**：各类门槛下可测率，说明样本选择偏差。
6. **证据链案例**：从实际表单状态到候选、反馈和政策结论，每一步能追溯。

置信区间应以站点为聚类单位，避免把同站几十个候选当几十个独立网站。时间比较用同站配对；调整策略期间的数据属于开发集。若样本很小，应展示原始计数和不确定性，不仅给小数点后两位。

## 十三、必须守住的研究与安全边界

- “有顶会论文支撑”指真正复用/复现可核查方法，不是给任意模块贴一个引用。
- 标准可定义验证规则，但标准不是顶会论文；论文也不替代协议规范。
- 本地表单、合成数据和独立真值可以支撑算法实验；真实网站外推仍需额外验证。
- 不使用真实用户口令，不绕验证码，不尝试未经授权的账号接管、限速触发或注册批量滥用。
- 不将公开参数观测解释为密码学协议的端到端安全证明。
- 所有改变同步CHANGELOG，记录研究动机、模型假设、指标变化与反例，不只写“优化成功”。

## 最终建议

**继续做，但收窄目标。** 现有工程能支撑一个有明确方法、公式和图表的密码测量项目；目前缺的是经过对照验证的核心结论，不是更多功能按钮。

最值得投入的是“测得准、知道哪里测不准、解释为什么测不到”。把这件事做实，能够形成扎实的竞赛原型和进一步研究的起点。是否能写成高水平论文，应由实验收益、可复现性和相关工作比较决定，不能现在保证。
