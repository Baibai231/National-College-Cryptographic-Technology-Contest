# 01｜Frank Li 论文与当前项目：实现、差距和可深化之处

> 核查日期：2026-09-14。代码基线：`main@f0aa2ab`；保留的应用层研究分支：`cjx/b-series-local-20260914@24e9c09`。本文是研究审阅，不是新功能完成声明。配套阅读：[工程与数据审计](02_项目结构缺陷与实测数据.md)、[论文与研究路线](03_相关论文与可执行研究路线.md)。

## 一、先把“富兰克林的论文”对应关系说清楚

项目资料中那篇《A Large-Scale Measurement of Website Login Policies》的作者是 **Suood Al Roomi 和 Frank Li**，发表于 **USENIX Security 2023**。Frank Li 不是 Franklin；为避免继续混淆，以下称“登录论文”。本次在本地资料目录也找到了这篇论文的中文命名 PDF。原文见：[USENIX 论文与书目信息](https://www.usenix.org/conference/usenixsecurity23/presentation/al-roomi)。

同一团队还有《Measuring Website Password Creation Policies At Scale》，发表于 **ACM CCS 2023**，DOI：`10.1145/3576915.3623156`，以下称“创建政策论文”。它与我们现在的候选密码、长度边界、字符组合、允许项测量更直接相关。原文见：[作者提供的开放许可 PDF](https://faculty.cc.gatech.edu/~frankli/papers/roomi_ccs23.pdf)，[作者项目页](https://authenticationresearch.cc.gatech.edu/creation.html)。

**这两篇论文不能混成一篇：登录过程安全，和新密码能否被接受，是不同的测量对象。我们的项目目前更接近后者的低交互版本，加上前者所需的入口发现基础设施。**

## 二、登录论文做了什么，我们还差在哪里

登录论文从公开入口出发，通过自动创建和使用测试账号，研究凭据输入、传输、可恢复存储迹象、容错认证、错误反馈及限速。其不同实验实际覆盖约 1.8 万至 35.9 万站，分母随实验变化；不是每一站都测完全部指标。作者明确承认复杂流程、账号创建失败及自动识别误差带来的选择偏差，结果不能直接推广到所有网站。详见原文 §2–§3.5：[登录论文](https://www.usenix.org/system/files/usenixsecurity23-al-roomi.pdf)。

下面主要是对**本项目代码和证据边界**的分析，不是宣称已经复现该论文。

| 比较维度 | 当前项目实际情况 | 与完整登录安全实验的距离 |
|---|---|---|
| 研究对象 | 登录/注册流程分类，以及注册密码的前端接受反馈 | 分类标签不等于登录安全政策 |
| 账号条件 | 默认访客，不创建账号、不发送验证码 | 无法验证“合法账号可以登录、修改后口令不能登录”的闭环 |
| 入口识别 | 关键词发现、页面特征、状态导航、iframe/弹窗处理 | 有工程基础，但当前批量和网页登录都先走注册导航，需先修正 |
| 输入行为 | 找密码框、设置值、触发事件、读取反馈 | 尚不能把字段颜色解释为服务端验证结果 |
| 凭据传输 | 有安全信号观察模块；B 分支有更深入的网络/协议观察器 | 必须将真实请求证据与页面声明区分，不能仅凭页面 HTTPS 判定整个流程 |
| 存储保护 | 没有数据库访问或完整账号恢复实验 | 不知道服务端是否使用 Argon2/bcrypt、盐及参数；也无法证明不存明文 |
| 容错登录 | 没有授权账号下的可重复正确/错误口令对照 | 不能测量服务端大小写折叠、截断或规范化后的认证语义 |
| 枚举与限速 | 默认没有对真实账号的相关实验 | 不应将一次错误提示或一次验证码出现直接当成全面结论 |
| 认证协议 | 主分支 WebAuthn 主要是 DOM 信号；B 分支有参数观察与边界声明 | 看到协议调用仍不等于签名、challenge、origin 的服务端验证正确 |
| 证据价值 | 能给出“访客路径到哪里被挡住、观察到什么”的证据 | 如果据此出“网站整体安全评分”，结论超出实际观测 |

### 不能用“没做什么”贬低论文

登录论文没有把所有网站安全问题都包进去，不是它失败了，而是它定义了自己的研究范围。我们没账号、没完整服务端闭环，是自己的实验条件限制，不能反过来说成“我们比它更轻量，因此结论更全面”。

适合继承的是：**每个安全主张对应独立实验；每个实验给自己的分母；失败和未测保留为未知；先验证实验判定器，再用它产出大规模结果。**

## 三、创建政策论文：真正值得继承的方法

以下基于作者开放许可原文 §3、§4。文中模型和实验的数字均属于论文的历史数据，不是我们的成绩。[CCS 2023 原文](https://faculty.cc.gatech.edu/~frankli/papers/roomi_ccs23.pdf)

### 3.1 它不是“找密码框，再看一段提示词”

其流程包含：注册入口发现、表单识别、补齐注册所需字段、识别注册是否成功、候选密码试验、参数推断和最终一致性检查。注册结果识别使用学习模型；论文报告的 **91.3% 是注册结果分类器的交叉验证准确率，不是整个政策测量器在任意网站上的准确率**。

这与我们默认只填密码框、不提交的 inline 模式有根本区别：

- 论文尝试观察注册是否成立，结果更接近服务器实际接受条件，但需要账号、额外字段和更高实验成本。
- 我们默认观察前端反馈，交互更少，但测得的首先是**前端接受判定**。除非有授权实验对照，否则不能自动升级为服务器政策。
- 原文也考察了前端规则的可见性；其中随机 200 站的文本、客户端规则、强度计比例，是特定样本和定义下的历史结果，不能套用成“今天只有这些比例的站支持 inline”。

### 3.2 参数化规则与受控变异

论文建模的不只是最短长度，还包括字符类最低数量、组合要求、特殊字符、重复/序列/字典/身份相关限制、短或长的数字密码例外及泄露密码等。先找到可接受的基准密码，再有控制地改变某个属性，避免同时破坏其他规则。

我们也使用类似的 `restrictive`、`permissive` 字段族，说明方向确实有论文来源。但“字段名字对应”不代表“每个字段已经有可靠实验”。特别是：

1. 测身份相关规则，需要密码内容与当前填写的账号身份实际绑定。
2. 测某个字符被禁止，需要确保拒绝不是长度或其他规则引起。
3. 测弱口令名单，需要样本首先符合其他政策。
4. “一个样本被拒绝”不能证明网站拒绝这一属性的所有实例。

### 3.3 长度二分不是我们新发明的方法

论文已使用长度二分搜索，并为其他参数安排探测次序和一致性校验。我们 `utils/adaptive_policy.py` 的长度二分有实用价值，但**不能将“用了二分”写为相对该论文的创新**。

对于固定其他属性、单调的长度谓词，二分需要约：

\[
Q_{\mathrm{length}}=O(\log_2(U-L+1)).
\]

这是算法复杂度，不是测量正确性证明。网站若存在“短密码必须混合字符，长密码可只用字母”等条件规则，则沿某条构造路径找到的阈值不一定是全局最短长度。

### 3.4 论文自己的筛选也非常明显

其规模大致经历：100 万目标 → 约 14.1 万注册页 → 约 5.9 万至少一次提交 → 约 2.6 万完成评估 → 一致性过滤后 **20,119** 站。它不是“100 万站都完整识别”。原文还明确讨论静态政策假设、复杂流程、验证门槛和自动化失败造成的局限。[原文 §3.8、§4.1](https://faculty.cc.gatech.edu/~frankli/papers/roomi_ccs23.pdf)

我们可以借鉴其漏斗，但不能只模仿最终完成数：**要研究被过滤的站是否恰好具有不同的政策或门槛。**

## 五、用当前数据定位差距，而不是凭感觉

历史基线文件 `reports/archive/policy_coverage_baseline_20260911.json` 中，303 个注册站：记录到密码框 **61**，执行主动测量 **16**，现有门控判为完整 **5**。因此：

\[
\frac{5}{303}=1.65\%,\qquad
\frac{16}{61}=26.23\%,\qquad
\frac{5}{16}=31.25\%.
\]

这些是现有统计定义下的覆盖/完成率，**不是准确率**。本次审计发现部分阶段定义会过度推断，数字应保留原口径并在修复后重算，而不是悄悄改写旧基线。

最新服务器实验则是另一批样本：1000 个目标，预检通过 413，完成 826 条唯一双入口分类任务，其中注册侧记录 `password_step_reached` 31 条。**这次尚没有新增第三阶段口令政策测量结果。** 两批样本不同，不能用 61/303 与 31/413 直接证明性能退步。

与论文的合理比较不是“它两万站、我们五站，所以我们没价值”，而是：**它选择了更强的交互观测条件；我们选择低交互之后，应将可观察性、判定可靠性和成本作为自己的核心研究对象。**

## 六、建议基于论文做的修改

### 第一优先级：修复实验语义，而不是添加安全项目

1. 登录明确使用登录发现，注册使用注册发现；结果记录请求意图、实际表单角色、路径证据和重定向链。URL 是辅助证据，不能仅凭 `/register` 字符串判定所有页面。
2. 每条探针绑定 `run_id / session_id / form_id / phase / probe_id`；正负对照必须来自同一个可比表单状态。
3. 将 `frontend_observed`、`frontend_active`、`server_confirmed` 分开；未知不得被强制补为 False。
4. 不再要求固定 `a` 必须被拒。若它接受，保留“弱候选被接受”证据，尝试其他有明确差异的对照；无法建模就返回有限结论。
5. HTML 长度限制作为声明/客户端约束保存，主动探测值另存；不能给它未经校准的 1.0 概率。

### 第二优先级：把判定器本身做成可评估对象

定义候选密码为 x，表单上下文为 c，观测为 z：

\[
O(x,c,z)\in\{A,R,\bot\}.
\]

其中 A/R 是接受/拒绝证据，\(\bot\) 是无法判断。上下文至少包括表单版本、是否获得焦点、事件顺序、验证请求是否完成、其他必填项是否门控。前端判定器与授权服务端真值应分别命名为 \(O_f\)、\(O_s\)。

\[
\mathrm{agreement}=\frac{\sum_i\mathbf1[O_f(x_i)=O_s(x_i)]}
{|\{i:O_f(x_i),O_s(x_i)\ne\bot\}|}.
\]

同时报告弃权比例，不能通过拒绝回答困难样本来制造高一致率。这是拟议评估设计，不是当前已有实验结果。

### 第三优先级：从“猜一条规则”改成“维护尚未排除的规则”

设候选政策集合为 \(\Theta_0\)，每轮排除与可靠观测矛盾的政策：

\[
\Theta_{t+1}=\{\theta\in\Theta_t:\theta(x_t)=y_t\},\quad y_t\ne\bot.
\]

如果集合为空，优先检查噪声、页面状态或模型表达能力，而不是强行给完整政策。这是我们建议新增的版本空间方法，**当前代码并未实现通用后验或信息增益优化**。

可以比较固定候选序列、当前二分/组合策略、版本空间策略。在相同预算、相同站点、相同安全边界下，比较规则预测误差、弃权率、探针数和耗时。若要使用信息增益，必须明确先验和噪声模型，不能只把公式写进论文。

## 七、什么可能有研究价值，什么不能称创新

| 不宜作为创新声明 | 值得形成待验证假设 |
|---|---|
| 长度二分、候选集、有限状态图、网站报告、加入大模型 | 带异步噪声和门控的三态判定器是否在相同预算下更可靠 |
| 只填密码框，所以可全面判断安全 | 低交互观测在哪些条件下与服务端接受一致，在哪些条件下必然不足 |
| 测中文站，所以天然新颖 | 中文/移动验证流程是否产生可量化的系统性观测偏差 |
| 支持更多字段名 | 新增政策模型是否提高独立保留集上的预测能力 |
| 找到几个提示矛盾 | 矛盾是否可重复、可归因，并影响弱口令选择或凭据暴露 |

**结论：不建议推倒重来，也不建议继续泛化成“全能网站安全扫描器”。最有依据的深化方向是“受限交互条件下的口令政策可靠推断与可测性偏差”。** 分类器为它服务，展示网站负责证据呈现，少量授权样本站提供服务器对照。能否成为论文创新，需要完成基线复现、同条件对比和相关工作查重后再判断。
