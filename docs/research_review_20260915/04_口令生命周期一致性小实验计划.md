# 接下来我们要做什么

## 目标

先做一个小实验：检查同一个系统在注册、登录、修改和重置密码时，对密码的处理是否一致，是否存在保护失效的问题。

## 具体测什么

1. 注册不让设置的弱密码，修改或重置时能不能设置成功？
2. 设置长密码后，只改最后几个字符，还能不能登录？
3. 改变密码的空格、大小写或Unicode字符后，系统会不会把不同输入当成同一个密码？
4. 修改或重置完成后，新密码能不能登录，旧密码是否失效？

## 怎么做

- 在组员各自的电脑或团队授权的测试环境中部署一个开源认证系统，不限定操作系统；使用自有测试账号，不测试未授权网站。
- 人工找到入口，先不依赖现有分类器，也不重构整个旧项目。
- 每次只改变一个条件，以实际设置和登录结果为准，不只看红框和提示。
- 发现异常就重复测试、查看源码，排除程序误判；差异不一定是漏洞。

## 最后交什么

先用三天左右验证可行性，交一张表：**测了什么、预期怎样、实际怎样、能否复现、原因是什么。**

有稳定且有安全影响的问题，再扩大实验；只有已知现象或没有值得深入的发现，就调整方向。不承诺一定发现漏洞。

方法参考：[Frank Li等人的USENIX Security 2023登录政策研究](https://www.usenix.org/conference/usenixsecurity23/presentation/al-roomi)。先借鉴受控账号和正确/错误密码对照方法，不把复现本身当创新。
