# Frank Li 两篇原始论文与当前项目的详细比较

## 核心判断

当前项目不是对原论文的完整复现，也不能因默认不创建账号就宣称比原论文更全面。它已经形成认证入口发现、流程分类、低交互口令探测、证据落盘与人工协作展示的工程体系，但在**判定器正确性、政策语义和大规模可测性**上仍未达到稳定研究工具的程度。

最新实验的正确表述是：1000个目标中413个通过预检，31个注册密码框候选进入第三阶段；23个在该轮保留密码步骤，10个留下主动探针，6个产出长度和组合结果，2个满足当前全部完整性门控。不能缩写成“只有2个网站支持口令政策测量”。[^3]

审阅基线是 `main@f0aa2ab2a0484174a03cf806d7e774efae9ab520`，与服务器第三阶段独立代码快照相同；B系列分支 `cjx/b-series-local-20260914@24e9c09` 单独评价。实验完成后未将B系列合并，也未修改内核后重跑。本报告中的改进均为建议，不是完成声明。

## 一、最初的论文究竟是哪一篇

| 论文 | 作者与发表 | 主要对象 | 与项目关系 |
|---|---|---|---|
| A Large-Scale Measurement of Website Login Policies | Suood Al Roomi、Frank Li；USENIX Security 2023 | 登录流程各阶段的政策与安全行为 | 最初资料中的论文；入口发现只是其基础设施 |
| Measuring Website Password Creation Policies At Scale | Suood Alroomi、Frank Li；ACM CCS 2023；DOI 10.1145/3576915.3623156 | 新密码的接受规则与黑盒推断 | 与目前候选密码、长度、组合、允许项模块直接对应 |

## 二、登录论文：它完成了什么、没有证明什么

### 2.1 它的实质成果

登录论文不仅识别页面，还创建和使用测试账号，研究凭据输入、传输、可恢复存储迹象、容错认证、登录错误反馈及限速。不同实验有效样本约为1.8万至35.9万站，并非所有站均完成全部项目。表单检测采用SVM：注册表单准确率94.6%、precision 77.1%、recall 99.5%；登录表单为94.0%、94.5%、96.3%。这些是特定分类子任务的评价，不是整站安全判断准确率。[^1]

### 2.2 它的证据边界

作者承认复杂流程、无法完成账号创建和自动化误判造成缺失与选择偏差。即使通过账号恢复发现可恢复口令，也不能由“未发现此现象”反向证明所有站采用合格哈希、盐和参数。它不是涵盖任意漏洞、账号生命周期和后台实现的网站安全认证。[^1]

### 2.3 与当前项目逐项比较

以下表格重点评价本项目，而不是重述论文。

| 维度 | 当前代码/结果 | 结论和差距 |
|---|---|---|
| 入口与表单 | `login_link_discovery.py`、`page_detector.py`、`navigator.py`、`classifier_engine.py` | 有多视图、iframe及导航基础，但最新272条分类任务因页面不可识别停止 |
| 登录/注册分离 | `scripts/run_measurement.py:230`、`webapp/app.py:1243` 均先调用注册导航 | 页面展示分栏分开，不代表浏览器实际测量路径分开；登录结果受污染风险已由代码确认 |
| 真实账号 | 默认不注册、不登录、不发送验证码 | 无法形成正确账号/错误口令的服务端对照闭环 |
| 凭据输入 | `TestPassword` 填充、blur、状态读取 | 能观察前端行为，不能直接验证登录认证逻辑 |
| 安全传输 | 主分支有被动信号观察 | 页面HTTPS、表单action或公开参数仅支持相应局部结论 |
| 口令存储 | 没有数据库或授权恢复闭环证据 | 不知道真实哈希算法、成本、盐和存储方式 |
| 容错、截断、规范化 | 主要测注册字段的接受反馈 | 不知道服务端登录是否接受大小写变体或截断后的密码 |
| 限速、枚举 | 默认实验不验证真实账号的这些行为 | 不应将验证码出现、单次错误消息当作完整安全验证 |
| MFA/Passkey | main的WebAuthn主要为DOM信号；B分支有更深入观察器 | 多种入口不等于强制MFA，challenge长度不等于服务器验证正确 |
| 可重复验收 | 有测试与历史回归记录，但本批无独立人工全量真值 | 不能报告最新分类真实准确率，更不能将826个结束任务当成功网站数 |

**值得继承的不是“多测几个安全指标”，而是每个结论对应独立实验条件、独立有效分母和明确失败处理。**

## 三、创建政策论文：我们实际继承的方法

### 3.1 实验链与两个学习判定器

论文把入口发现、注册表单识别、补齐字段、执行注册、识别注册结果、政策推断和最终筛选连成完整链。注册结果模型使用XGBoost，论文的91.3%是注册结果分类器交叉验证准确率，不是整个政策系统的准确率。实际注册成功比单纯前端颜色更接近服务器接受，但也受结果分类错误影响。[^2]

我们的默认链是“到注册密码框→只填密码→触发反馈→推断”。不创建账号是合理的低交互边界，却使观测对象主要成为**前端接受判定**。前端与服务端是否一致，需要额外授权子样本验证，不能由前端探针自行证明。

### 3.2 参数化政策与受控变异

原文研究长度上下限、字符类最低数量、组合、特殊字符、重复/序列/字典/个人信息相关规则、数字口令例外和泄露口令等。核心思想是先找到可接受的锚点，再改变目标属性、尽量保持其他限制满足，并进行一致性检查。[^2]

项目 `restrictive` / `permissive` 的字段体系与此对应，但实现存在关键语义差距：

- `identify_permitted_sequences` 仅在某些测试接受时写入 `p_dict`、`p_info`；未构造、被拒和未知没有完整区分。
- `p_info` 用生成的 `self.username[:3]` 构造密码，而inline不填写该身份；即使输出True，也不能解释成“接受包含真实账号信息的密码”。
- 一些字符测试通过替换锚点尾部实现。如果替换恰好破坏唯一数字等必要属性，拒绝可能不是由于所测字符被禁止。
- 6个实质结果中，4个因允许项不完整未通过总门控，不等于这些站没有inline或前面所有规则无价值。

### 3.3 长度二分已在论文中使用

原论文已有长度二分搜索和候选顺序设计。`AdaptiveLengthPlanner` 的实现有工程价值，但“二分节省查询”不是相对该论文的新颖贡献。[^2]

对于保持其他属性不变且单调的长度谓词：

\[
Q=O(\log_2(U-L+1)).
\]

公式成立依赖可接受锚点与单调性。存在“短密码须多字符类、长密码放宽”等条件规则时，沿一个构造族找到的阈值不一定是全体密码的最小长度。当前 `AdaptiveConditionalPolicyPlanner` 已探索有限的放宽分支，因此不能说程序只会AND；但它仍不是任意逻辑政策的完备推断器。

### 3.4 论文的大规模结果也经过筛选

创建政策论文的历史实验从100万Tranco域名出发，找到约14.1万注册页，约5.9万可进行至少一次提交，约2.6万完成评估，过滤后得到 **20,119** 个政策结果，并随机人工核验100个已评估站。数据采集于2021年12月，2023年发表。不能把它当成2026年网页现状。[^2]

作者明确讨论静态政策假设、复杂多步注册、额外验证、费用或离线成员资格等限制。因此“论文没有解决所有网站”是真的，“这些都没有人研究过”则不成立。

值得特别注意的是，它发现部分站允许一字符口令；我们的固定负对照却要求 `a` 必须被拒才能继续。**这个前置假设会漏掉本应重点发现的弱政策。** 本批Stripe的一字符探针被程序标成accepted后退出，但其接受来自异步复验分支；这只能说明程序判定链冲突，不能据此宣称Stripe服务器接受一字符口令。

## 五、项目已有的实质进步

与简单分类脚本或原始顺序探测相比，现有工程并非没有成果：

1. 将可见表单、路径、阻断、方法与最终结果保存，支持解释为何停止。
2. 默认限制为inline，避免把填表探测无意扩大为账号创建。
3. 引入accepted/rejected/inconclusive、部分检查点、超时恢复和浏览器进程管理。
4. 有自适应长度、字符类组合和有限条件政策探索，不必每次穷举全部候选。
5. 有正式结果与人工结果分离、SQLite展示索引、任务队列和重新测试入口。
6. B分支保留证据层级、公开WebAuthn观察、强度计指标等研究代码，但尚非main的全部能力。

这些应写为工程贡献。是否成为研究贡献，要用对照和消融证明它们改善了可靠性、覆盖或成本，而不是以代码行数或提交次数代替。

## 六、可以基于论文做哪些修改

### 6.1 第一组：不改研究目标，先修实验定义

登录明确走登录导航；注册走注册导航。对同一身份提供方共享入口，不仅看URL，还检查表单角色、按钮文案与已观察动作。批量政策测量限定signup，不能保留login标签却执行注册政策测试。

将结果分为“声明的规则”“主动前端观察”“授权服务器验证”。HTML maxlength记录在第一类或客户端约束类，不能自动获得 `measured, confidence=1.0`。对未经校准的固定置信值改用明确的启发式标签。

### 6.2 第二组：统一反馈判定与对照

当前 `_detect_method` 的预检查与 `TestPassword.test_one_password` 是两套判定。建议由同一判定器负责两阶段，用相同的上下文和返回契约：

\[
O(x,c)\in\{A,R,\bot\},
\quad c=(session,document,frame,form,phase,events).
\]

这是建议的接口模型。A/R必须附原因和适用上下文，\(\bot\)保留为未知。不能把CSS类里出现invalid当成真实伪类已激活；不能让异步“最终valid”绕过对照约束；对重复同原因拒绝，先检查表单和仪器状态。

### 6.3 第三组：候选空间、规则空间与观察空间分开

设政策候选集为 \(\Theta_t\)，可靠观测为 \((x_t,y_t)\)。无噪声时可更新：

\[
\Theta_{t+1}=\{\theta\in\Theta_t:\theta(x_t)=y_t\},\quad y_t\ne\bot.
\]

真实网页有噪声，不能机械排除全部不一致规则，应允许重复验证或显式噪声模型。集合为空意味着观测矛盾或模型不足，而不是允许程序强行输出完整政策。当前实现还不是一般版本空间或贝叶斯信息增益系统，这部分属于拟议扩展。

对无法区分的政策输出等价类/区间，对无法构造的探针输出 `not_constructible`。不应为追求complete把缺失项填成False。

### 6.4 第四组：从字段齐全转向独立预测验证

给定未参与推断的候选集T，比较推断规则 \(\hat P\) 与可靠判定器：

\[
E_{pred}=\frac{\sum_{x\in T:O(x)\ne\bot}\mathbf1[\hat P(x)\ne O(x)]}
{|\{x\in T:O(x)\ne\bot\}|}.
\]

同时报告弃权率、探针数、时间和跨轮一致率。若O仍是前端判定器，此指标只是前端预测误差；服务端一致性需要授权账号或本地真值服务器的额外实验。

## 七、最有希望的研究定位

建议聚焦 **“低交互条件下的口令政策可靠推断与不可观测性”**，将分类器作为认证路径和测量边界识别器，而不是独立堆叠网站功能。

可检验的假设包括：统一且可弃权的判定器能否减少误接受；属性约束保持的候选构造能否降低混杂；显式建模不可观测性是否改变对弱政策的总体估计。这些假设需要实验，不因写出公式就成为创新。

不宜作为创新：二分搜索、有限状态图、支持中文页面、生成安全报告、给每项贴论文引用。也不宜声称访客模式验证了服务端口令存储、强制MFA、恢复安全或WebAuthn断言校验。
