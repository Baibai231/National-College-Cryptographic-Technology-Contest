# ZipfGuard 项目状态

更新日期：2026-09-18

## 项目目标

在完全本地、可复现的合成数据上，构建“口令分布测量—候选策略—用户响应—自适应攻击—风险与成本权衡”的完整实验闭环，并形成可演示、可验证、可答辩的竞赛作品。

## 当前范围

- 主线只使用本地合成用户和合成口令。
- 不使用真实网站口令、身份信息或在线认证接口。
- PassLLM 暂不作为主线依赖；频次、字典和 n-gram 攻击基线已完成。
- 攻击者默认知道口令策略，并允许针对新策略重新训练或重排。
- 主要评价指标是固定预算下的 `cracked@K`、用户成本和最坏攻击者风险，不把形式复杂度直接等同于安全性。

## 当前基线

- Python 3.13.9、NumPy 2.5.3 可用。
- 远端集成后的 Python 单元测试 30 项全部通过；缺少本地 PassLLM 时会验证并使用 `local-ngram` 回退状态。
- 三种有限支持分布模型、风险阈值、基础策略、CLI、Web 原型和报告导出已存在。
- 三类攻击器共享统一排名接口，并按 train 拟合、validation 选参、test 评价的协议运行。
- 策略实验保留所有用户，记录重新选择行为，并对比冻结与自适应攻击。
- M4 在 validation 上执行约束搜索与 Pareto 筛选，选定三档后才生成 test 结果。
- JavaScript 红队原型可以运行，已包含固定后缀负面对照、用户转换和自适应 n-gram 攻击。
- Python 分布、策略与攻击实验已统一使用同一份固定划分的合成用户数据。
- Rockyou 去重字典不进入分布建模结论，仅保留为未来字典攻击候选源。

## M1 验收记录

- 新增统一合成用户数据生成器，默认规模 20000，固定 60/20/20 划分。
- 分布建模使用其中 12000 个训练用户和 4000 个验证用户。
- 策略实验使用同一数据集的训练用户和 4000 个测试用户。
- 聚合频次输入不再附带无关的合成策略结果。
- 默认演示的数据集、模拟元数据和所有策略结果使用同一个数据集 ID。
- 2026-09-18：13 项单元测试全部通过；默认快速实验成功生成 Markdown/JSON 报告。

## 当前状态：M4 已完成

M4 已把约束策略搜索、Pareto 前沿和三档建议接入 Python 主流水线；M5 及后续阶段尚未开始。

## M2 验收记录

- 新增统一 `fit_select_rank` 攻击器接口和不可变排名结果格式。
- 实现训练集频次、公开合成字典、字符 n-gram 三类确定性攻击器。
- 字符 n-gram 只使用 train 拟合，使用 validation NLL 选择阶数与平滑参数。
- 在固定 test 用户上输出 cracked@100/1K/10K、覆盖率和逐点 95% Wilson 区间。
- 攻击者对比表已接入 JSON 与 Markdown 流水线报告，固定预算不因候选空间较小而被截断。
- 2026-09-18：17 项单元测试全部通过；5000 用户快速实验成功生成 JSON 与 Markdown 攻击对比报告。

## M3 验收记录

- 被策略拒绝的用户依次尝试可预测修补和公开合成随机短语，最终记录仍保留原 `user_id` 与数据划分。
- 输出初始接受率、最终完成率、修改率、总尝试数、修改用户平均尝试数和修改前后分布摘要。
- 冻结攻击沿用原始 train 排名；自适应攻击在响应后的 train 重新拟合，并仅用响应后的 validation 选参。
- 每个策略、攻击器和预算均输出冻结风险、自适应风险与适应增益，并汇总最坏攻击者风险。
- 测试覆盖用户数守恒、响应确定性、候选空间覆盖、最终策略合规和 test 不参与训练或选参。
- 2026-09-18：22 项单元测试全部通过；5000 用户快速实验成功生成 M3 JSON 与 Markdown 报告。

## M4 验收记录

- 从最小长度、字符类别、年份后缀、键盘走查和常见词根等动作枚举 26 个唯一的单规则与双规则候选。
- validation 搜索固定使用频次、公开字典和固定参数字符 n-gram 的最坏自适应风险，不读取 test 指标。
- 用户成本综合修改率、平均尝试数和长度增加；规则成本按活跃规则数归一化，并执行完成率、修改率、尝试数和总成本约束。
- 以“最坏自适应风险”和“总成本”为双目标构造 Pareto 前沿，从中选择低摩擦、均衡、高防护三档。
- 仅选中的三档使用完整攻击器配置生成 test 最终结果；行为等价的候选复用攻击计算，不改变选择逻辑。
- 2026-09-18：26 项单元测试全部通过；测试覆盖候选去重、支配关系、三档唯一性和 test 不影响 validation 选择。
- 2026-09-18：5000 用户快速实验枚举 26 个候选、归并为 10 个攻击场景并得到 4 个 Pareto 点，成功输出三档最终 test 结果。
- 2026-09-18：与远端队友的空样本语义回归合并后，全量 30 项测试通过。

## 已知风险

- 当前用户响应是规则化合成模型，只用于验证因果机制；真实部署前必须使用授权用户研究校准修改概率与记忆成本。
- 当前 M4 成本权重和约束是可复现实验配置，不是经过真实组织或用户研究确认的部署阈值。
- Python 和 JavaScript 存在两套红队逻辑，长期会发生结论漂移；主线将统一到 Python，JavaScript 暂作参考与对照。
- 单一随机种子只适合演示；正式实验至少使用 5 个种子并报告均值与区间。
- 合成数据只能验证方法和因果机制，不能声称代表真实世界破解率。

## 每次迭代的固定检查

1. 运行单元测试。
2. 运行一个小规模快速实验。
3. 核对数据集 ID、随机种子、划分、攻击器和策略版本。
4. 检查是否存在训练/测试泄漏。
5. 将结果与限制写入报告，不只保留成功案例。
